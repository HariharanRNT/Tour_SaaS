# Database Migration Guide

Alembic is now the **single source of truth** for all schema changes.
Do **not** create new `update_schema.py`, `force_db_fix*.py`, or raw SQL files in the backend root.

---

## Quick Reference

```bash
# From: d:\Hariharan\G-Project\RNT_Tour\backend

# Check current revision of connected DB
alembic current

# View full migration history
alembic history --verbose

# Apply all pending migrations (upgrade DB to latest)
alembic upgrade head

# Roll back one migration
alembic downgrade -1

# Roll back to a specific revision ID
alembic downgrade 0001

# Stamp an already-up-to-date DB (no DDL, just record the revision)
alembic stamp head
```

---

## How to Add a Schema Change

### 1. Edit your SQLAlchemy model
Make the change in `app/models/__init__.py` (or the relevant model file).

### 2. Auto-generate a migration
```bash
alembic revision --autogenerate -m "add_column_packages_featured"
```
This creates a new file in `alembic/versions/` with `upgrade()` and `downgrade()` populated from the model diff.

### 3. Review the generated file
Open the file in `alembic/versions/`. **Always review autogenerated migrations** before applying — Alembic can miss some complex cases (e.g. custom types, computed columns).

### 4. Apply the migration
```bash
alembic upgrade head
```

### 5. Commit both files
Commit the model change **and** the migration file together so they stay in sync.

## Structure

```
backend/
├── alembic.ini                   ← Alembic configuration (no credentials — URL from .env)
├── alembic/
│   ├── env.py                    ← Async SQLAlchemy setup, reads DATABASE_URL from settings
│   ├── script.py.mako            ← Template for new migration files
│   └── versions/
│       └── 0001_baseline_...py  ← Initial baseline (all pre-Alembic changes documented)
```

---

## Rules Going Forward

| ✅ Do | ❌ Don't |
|---|---|
| `alembic revision --autogenerate` | Create new `update_schema.py` files |
| Review generated migrations before applying | Run raw `ALTER TABLE` in Python scripts |
| Commit model + migration together | Hardcode credentials in `alembic.ini` |
| `alembic stamp head` after manually applying DDL | Edit existing applied migration files |
| `alembic upgrade head` in CI/CD before app starts | Run `force_db_fix*.py` on production |

---

## Environment Notes

- **Development (SQLite):** `sqlite+aiosqlite:///./tour_saas.db` — uses `batch_alter_table` mode for SQLite's limited ALTER TABLE support.
- **Production (PostgreSQL):** `postgresql+asyncpg://...` — uses native `ALTER TABLE ADD COLUMN IF NOT EXISTS`.
- The `DATABASE_URL` is always read from `.env` via `app.config.settings`. Never hardcode it in `alembic.ini`.
